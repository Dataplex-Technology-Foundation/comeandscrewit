## 1. Problem

Pages is `build_type: legacy`, `source: {branch: main, path: /}`. `legacy` is **not** a verbatim
copy — it is a Jekyll build, which:

- **excludes** dot-prefixed paths (`/.gitignore`, `/.github/…`, `/CNAME` are all 404), and
- **transforms** markdown, publishing each internal `.md` twice — raw, and as a themed HTML page
  with `<title>`, `og:site_name` and `<link rel="canonical">`.

```
https://comeandscrewit.com/reference/nws-grand-challenge-tracker.html   → 200
<title>USDA APHIS New World Screwworm (NWS) Grand Challenge — Project Tracker | comeandscrewit</title>
<link rel="canonical" href="http://comeandscrewit.com/reference/nws-grand-challenge-tracker.html" />
```

The rendered twins are the worse half: a canonical tag presents internal research to crawlers as
first-class site content.

**Exposure at the start of this work: 25 URLs = 18 raw paths + 7 rendered pages.** (v2 said
"19 raw + 6 twins" — wrong split, right total. The 7th rendered page is `/assets/img/`, a
directory index Jekyll generates from `assets/img/README.md`; it is not a `.html` twin of a
tracked path, which is why any enumeration keyed on `git ls-files` + `.html` misses it.)

PR-0 has already closed 2 of the 25 by moving `assets/img/README.md` out of the asset tree.
**23 remain.** The live list is generated by `scripts/0002_exposure_inventory.sh`; no table in
this document is authoritative for it — hand-maintained lists are how v1 undercounted by 46%.

Second exposure, same root cause: `Dockerfile` does `COPY . /usr/share/nginx/html` then `rm -f`
four files, so `docker compose up` served the same material on `localhost:8093`.

## 2. Goals / non-goals

**G1** Nothing outside the publish set is reachable on the domain. **G2** Accidental publication
is impossible; deliberate publication requires editing the publish workflow. **G3** The layout
makes the boundary obvious. **G4** Automation is *fixed* (it is broken — §4) and keeps working.
**G5** The publish path is more secure after. **G6** Zero downtime, verified by byte-identity.
**G7** Every action is a re-runnable numbered script in `scripts/`.

**NG1** No history rewrite (§3 D4). **NG2** No change to site design or markup beyond PR-0's
mechanical pass. **NG3** No static-site generator, bundler, or build-time dependency.
**NG4** The repo stays public — Pages requires it on the org's Free plan.

## 4. Automation is broken — and the fix is not mine to make

Every scheduled run since 2026-08-21 fails at PR creation:

```
##[error]GitHub Actions is not permitted to create or approve pull requests.
```

The scraper succeeds and detects changes, so **fresh outbreak data is fetched and discarded
daily**. `scripts/0004_repo_settings.sh` attempted the repo-level flag and got:

```
409 Conflict — "The organization does not allow GitHub Actions to create or approve pull requests"
```

**This is an organisation policy.** `dts-dataplex` is repo admin, not org owner. **Requester
action R1 (§10).** Until it lands, §11's automation criteria are untestable and are marked
BLOCKED, not failed — v2 made an unsatisfiable criterion, which is what v1 was failed for.

## 5. Layout

```
site/          ◀── the publish root; this directory IS the artifact
internal/      ◀── automation/ tests/ reference/ container/ docs/
scripts/       ◀── numbered operational scripts
.github/workflows/   publish.yml ci.yml daily-outbreak-data.yml weekly-project-rankings.yml
```

Contributor rule, one sentence: **if it is not under `site/`, it is not on the website.** Stated
in the new root `README.md`, in `CONTRIBUTING.md`, and in the gate's failure message.

`CNAME` is **excluded from the artifact**: under `build_type: workflow` the domain comes from the
Pages API setting and a `CNAME` file is ignored. It is 404 today; shipping it would create a new
public URL. `0007` asserts the API `cname` instead.

### 5.1 Disposition — generated, never written by hand

`scripts/0002_exposure_inventory.sh --disposition` maps every tracked path to its
destination and whether it is published, derived from `git ls-files`. It reports
`*** NO DESTINATION DEFINED ***` for anything unaccounted for.

**No prose table replaces it, and this document deliberately states no path count.**
A hand-maintained list has now been wrong three times in three drafts, each time in the
section rewritten to fix the previous failure: v1 listed 13 of 25 exposed URLs and its
acceptance criterion inherited the undercount; v2 deleted the table, which is how a `.md`
inside the asset tree became a site-down risk at cutover; v3 restored it and still omitted
`internal/docs/removed-content-inventory.md` — a file whose publication would have restored,
at a canonical-tagged URL, the verbatim disclosure this work exists to remove. The list is
not something a human keeps correct, so nothing downstream reads one.

**PR-0 additionally makes the exposure close on merge rather than at cutover.** Because
Pages still builds with Jekyll, every tracked non-dot-prefixed path is published — so PR-0
adding an inventory of the removed notes would have published them. `_config.yml` now
excludes every internal path, and `scripts/0005`'s `check_jekyll_exclusions()` fails if any
tracked top-level path is neither in the publish set nor excluded, naming the URL it would
appear at. `_config.yml` is a denylist, which this plan argues against; it is transitional,
it is the only control available before the cutover, and it is deleted once the cutover is
verified.

`site/assets/img/` will be empty. `upload-pages-artifact` runs `--exclude=.[^/]*`, so a
`.gitkeep` is stripped from the artifact anyway.

### 5.1a Why moving the tree cannot break a link

References are **either document-relative or root-absolute**, and both resolve identically
because the artifact root remains the domain root. (v1 claimed "no absolute-path references"
and labelled it verified; it is false — `404.html` has 12 and `site.webmanifest` has 3.) The
property that actually needs guarding is the absence of `../` traversal, currently zero,
which the gate checks.

Constraint on future pages: `site-data.js:12` and `outbreak-map.js:41` fetch
`assets/data/outbreak-data.json` document-relative, so they resolve correctly only while
every page sits at root depth. A nested page would break them.

### 5.2 Path constants — eleven, across three scripts

v2's prose said "eight" while its own table listed eleven. Eleven is correct; all three
`REPO_ROOT`s change (`parent.parent` → `parents[2]`).

| File | Constants |
|---|---|
| `rank_projects.py` | `REPO_ROOT`, `TRACKER_FILE`, `RANKINGS_FILE`, `RANKINGS_HISTORY_FILE` |
| `refresh-outbreak-data.py` | `REPO_ROOT`, `DATA_FILE` |
| `scrape_outbreak_data.py` | `REPO_ROOT`, `OUTBREAK_DATA_FILE`, `OUTBREAK_HISTORY_FILE`, `PUBLICATIONS_FILE`, `SCRATCH_DIR` |

`SITE_ROOT = REPO_ROOT/"site"`, `INTERNAL_ROOT = REPO_ROOT/"internal"`, `SCRATCH_DIR` stays at
`REPO_ROOT/"scratch"` (matches `body-path: scratch/pr-body.md` and `.gitignore`).

**Seven workflow path references.** v2 named two; v3 named five and still missed the two
`run:` lines that actually invoke the scripts — the ones that break hardest:
`ci.yml:28` `scripts/requirements.txt`, `ci.yml:29` `tests/requirements.txt`,
`ci.yml:32` `py_compile scripts/*.py`, `ci.yml:53` `unittest discover -s tests`,
`daily-outbreak-data.yml:31` `scripts/requirements.txt`,
**`daily-outbreak-data.yml:41` `run: python3 scripts/scrape_outbreak_data.py`**, and
**`weekly-project-rankings.yml:31` `run: python3 scripts/rank_projects.py`**.

Anchoring rewrites to "constant-assignment lines and YAML path blocks" does not cover a
`run:` line, and nothing would catch the omission: `ci.yml` never executes the scheduled
workflows, and the criteria that would are BLOCKED on R1. `daily:41` also carries
`continue-on-error: true`, so the failure would surface only at the terminal `exit 1`.
Plus the `git diff` filters (`daily:46`, `weekly:36`) and `add-paths` blocks
(`daily:62-65`, `weekly:61-63`).

Rewrites are anchored to constant-assignment lines and the YAML path blocks. **No blind `sed`** —
`weekly:51-55` has `reference/…` in English prose in the PR body.

**Silent-data-loss hazard:** a missed `git diff` filter matches nothing → `changed=false` → no PR
→ data discarded → **job green**. §11 therefore asserts a seeded change produces a PR touching
exact paths, never merely "runs green".

**Expected first-run diff:** four `relative_to(REPO_ROOT)` calls write paths into generated
file *content*. They do not all become the same thing, and v3 wrongly said they did:
`rank_projects.py:134,194` and `scrape_outbreak_data.py:346` become `internal/reference/…`,
but `scrape_outbreak_data.py:326` is `OUTBREAK_HISTORY_FILE`, which under
`SITE_ROOT = REPO_ROOT/"site"` becomes **`site/assets/data/outbreak-history.json`**.
A fifth site, `refresh-outbreak-data.py:246`, prints to stdout only and changes no file
content. Pre-declared so none of it reads as a byte-identity violation.

### 5.3 Container

`COPY site/ /usr/share/nginx/html` replaces the `rm -f` denylist; `Dockerfile:3` becomes
`COPY internal/container/nginx.conf`. `docker-compose.yml` needs **both** `context: ../..` **and**
`dockerfile: internal/container/Dockerfile`. A `.dockerignore` is added — none exists, so the
whole repo including `.git` currently ships as build context.

The gate (`0005`) is shared by CI and `publish.yml` **only**. A Dockerfile `COPY` cannot invoke a
shell script, so the image reproduces the directory boundary but not the gate; §11 verifies the
image tree equals `site/` instead.

## 6. The gate

**Layer 1 — the directory.** `site/` is the artifact. Everything else is absent, not excluded.

**Layer 2 — checks over `site/`,** run in PR CI and again at publish:

1. **Extension allowlist**: `.html .css .js .json .svg .xml .png .jpg .webp .ico .webmanifest`,
   plus `robots.txt` **by exact name** — allowlisting `.txt` leaves a hole. (v2 said "denylist"
   in one section and "allowlist" in another; allowlist is correct and is what ships.)
2. **Symlink rejection**: `test ! -L site && find site -type l` must be empty. `upload-pages-artifact`
   runs `tar --dereference --hard-dereference`, so `ln -s ../internal site/docs` would publish the
   whole internal tree past **both** layers. Note the **absent trailing slash**: `find site/ -type l`
   dereferences the start point, so a `site` that is *itself* a symlink slips through.
3. **Placeholder tiers** (§7).
4. **Same-origin resolution**: every URL in HTML, JSON-LD and the webmanifest resolves to a file
   in `site/`. **Currently fails** — 4 missing images (§9.2).
5. **Orphan pages**: every `site/*.html` is in `sitemap.xml`, or reachable from `index.html`, or
   `noindex` **and** in an explicit `unlinked-pages` allowlist.
6. **Sitemap ↔ robots**: every `<loc>` absolute and resolving; no `noindex` page listed.
7. **No `../` traversal; no `http://` subresources.**

Failure messages name the path, the rule, and the remedy ("move it to `internal/`").

## 7. Placeholders

v1 said 215; three reviewers measured 229/234/235 with different regexes. **The spread is the
finding** — a scalar count is an artefact of its pattern. Hence no count is used as a baseline.

**Tier A — hard fail, no baseline. Matched on attribute and property *values only*, never
on whole lines.** `[OG IMAGE]` sits in an HTML comment on the same line as `og:image` on 14
pages, and `[SOCIAL LINK]` shares a line with JSON-LD `url` and `logo` in 13 of 14 files. A
line-scoped implementation would hard-fail 27 times on requester-blocked tokens. Scoped to
exactly what PR-0 clears and keeps clear:
`rel="canonical"`, `og:url`, `og:image`, `twitter:*`, `<loc>`, `robots.txt`'s `Sitemap:`, and
JSON-LD `url`/`logo`/`mainEntityOfPage`.

**`href`/`src`/`action` are deliberately NOT in Tier A.** v2 put them there and simultaneously
asserted Tier A would be empty after PR-0 — but 42 `href="[SOCIAL LINK]"` and 1
`action="[FORM ENDPOINT]"` remain, and both are requester-blocked. That is v1's signature defect:
an acceptance criterion the plan forbids itself from meeting. They sit in Tier B with a named
exception until §10 R2 supplies the values.

**Tier B — keyed inventory, may not grow.** A checked-in sorted `(file, token, count)` file,
diffed against the generated one. Fix-one-add-one fails (new key); reformatting is immune.
Scanned over `site/**/*.{html,xml,txt,webmanifest,json}` **only** — never CSS or JS, which hold
17 legitimate `[…]` attribute selectors and array literals. (`main.js:77` contains a real
`[FORM ENDPOINT]`, but inside a comment explaining the guard against it — the JS exclusion is
therefore deliberate and slightly lossy, noted here so a future reader does not assume otherwise.)

Detection: `\[[^\]\n]{2,80}\]` minus an explicit allowlist. Broad by default — the narrow pattern
is how v1 got it wrong.

## 8. Security

### 8.1 Improvements
1. Publish-everything → publish-one-directory.
2. Container denylist → same boundary; `.dockerignore` added.
3. **Enforce HTTPS on.** `https_enforced: false` today; `http://comeandscrewit.com/` returns 200
   with no `Location`.
4. Publish job: `contents: read`, `pages: write`, `id-token: write`,
   `persist-credentials: false`, `concurrency: {group: pages, cancel-in-progress: false}`.
5. `github-pages` env branch policy narrowed — **done**, stale `gh-pages` entry removed.
6. Untrusted HTML parsing runs only in `daily-outbreak-data.yml`, which has no `pages:`/`id-token:`.
7. **`sha_pinning_required: true` — done.** Platform now enforces what was convention.

### 8.2 Corrected claim
v2 said "the credential count is zero." False and self-contradictory: `id-token: write` mints a
signed OIDC JWT and `pages: write` is a new scope. Accurate: **no new long-lived secret;
`actions/secrets` remains 0.**

### 8.3 The guarantee
Not "structurally impossible". **Publishing internal content is impossible by accident, and
impossible at all without editing `publish.yml` or the gate.**

### 8.4 Residual risks
| Risk | Note |
|---|---|
| `publish.yml`/gate editable in one unreviewed commit | No branch protection, no rulesets. Recommended and **declined** (D3). ADR 0001's "no direct commits to `main`" stays unenforced. |
| `.html` carries arbitrary content | `site/internal-notes.html` passes. Accident-resistant, not adversary-resistant. |
| Pages revertible to `legacy` in one API call | `0011` re-runs as a drift check. |
| Old content fetchable via `refs/pull/*` | Accepted under D4. |

### 8.5 Observability
v2 rejected the `site`-branch design for going "stale silently", then adopted the same failure
mode — which **was already live and unnoticed for three days** (§4). `publish.yml` and both
scheduled workflows get an `on: failure` notification; `0011` runs weekly as a drift check.

**Sequence:** PR-0 → 0004 → PR-1 → 0007 → 0008 → PR-2 → 0011.

**Ordering is the safety property.** PR-1 + `0008` close the exposure *before* any file moves, so
PR-2 is a refactor with no live-cutover risk. Merging the move under `legacy` would leave `main`
with no root `index.html` and 404 the whole site until cutover.

**PR-1 ships `publish.yml` with `workflow_dispatch:` only.** The `push: [main]` trigger is added
in a follow-up commit *after* `0008` succeeds. Otherwise merging PR-1 fires the workflow while
Pages is still `legacy`, `deploy-pages` hard-fails, and `main` goes red before the cutover runs.

**`0008`** does: `PUT {build_type, cname}` → poll `GET /pages` to `status:"built"` →
`gh workflow run publish.yml` → `gh run watch` → verify → **separate** `PUT {https_enforced:true}`
(combining them risks `409` while a build is in flight) → auto-rollback if the run fails.

**`0008 --rollback`** refuses if `main:site/index.html` exists, printing the `git revert`
instruction — otherwise it would set `legacy`/`main`/`/` on a tree with no root `index.html`.
The `PUT` always sends `cname`: losing the domain means DNS re-verification and certificate
reissue ("up to 24 hours"), not a one-minute rollback.

|---|---|---|
| PR-1 | close it | none |
| 0008 | `--rollback` (guarded) | one deploy cycle; `main` untouched |
| PR-2 | close, or `git revert` | none — `0008` already guarantees only `site/` publishes |
| 0009 | re-runnable; `git reset --hard` | local |
